# StockLens AI

## 1. 产品简介

**StockLens AI 是一个自然语言智能选股与策略解释器。** 项目使用 Python 和 Streamlit，实现从投资意图表达、条件确认，到真实数据筛选和结果解释的 MVP 流程。

产品目标是将投资者模糊的语言转换为**可检查、可修改、可执行的数据条件**，并基于真实金融数据返回可解释的筛选结果。例如，用户输入“经营改善、估值合理、走势稳定”，系统将其转为营收增长、PE 上限和最大回撤上限，供用户确认后执行。

产品以“规则是否匹配”为输出，不把筛选结果等同于投资推荐。

## 2. 用户痛点

| 用户痛点 | 产品设计回应 |
| --- | --- |
| 传统选股工具要求用户先理解专业指标与参数 | 通过自然语言表达需求，再用可读卡片展示指标映射 |
| 大模型直接生成股票或行情，来源和准确性难以验证 | 将意图理解与金融数据获取分离，股票与指标来自 API 及其本地缓存 |
| 只有筛选名单，无法理解入选或落选原因 | 保留每个条件的判断记录，展示实际数据、筛选要求和原因 |
| 修改阈值后，不清楚候选范围为何变化 | 对比前后候选集合，展示新增、减少数量及变化说明 |

项目采用“自然语言理解 + 确定性筛选 + 数据解释”的组合，让用户能够检查和调整筛选过程。

## 3. 产品核心流程

```text
用户自然语言输入
        ↓
AI意图解析
        ↓
结构化条件
        ↓
用户确认 / 修改
        ↓
金融数据筛选
        ↓
结果解释
```

1. 用户输入需求，点击“解析需求”。
2. 页面以“AI理解你的需求”卡片展示条件；原始 JSON 保留在“查看结构化条件”折叠区。
3. 模糊或冲突的条件标记为 `unknown`，提示澄清并阻止执行；未提及或明确不关注的条件为 `disabled`，显示“未启用”，不阻止执行。
4. 用户可修改 PE 和最大回撤上限，再确认筛选。
5. 页面读取 `data/stock_dataset.csv`，交由确定性引擎逐只判断。
6. 表格展示全部股票及入选状态，点击行或使用选择框查看解释卡片；再次调整条件可查看前后对比。

模型输出结构示例（数值为策略阈值，不是股票金融事实）：

```json
{
  "conditions": {
    "growth_improvement": true,
    "pe_max": 30,
    "max_drawdown_max": 0.15
  },
  "need_clarification": false,
  "growth_condition": {"status": "enabled"},
  "pe_condition": {"status": "enabled"},
  "stability_condition": {"status": "enabled"},
  "conflicts": [],
  "interpretation": {
    "growth_improvement": "经营改善 → 营业收入同比增长率",
    "valuation": "估值合理 → PE(TTM)",
    "stability": "走势稳定 → 60日最大回撤"
  }
}
```

条件支持 `enabled`、`disabled`、`unknown` 三态，只有存在 `unknown` 才需要澄清。`conditions` 可以只包含启用项，例如“收入增长明显，不太关注短期波动”只启用经营改善。页面执行前将关闭的增长条件转换为 `false`、关闭的 PE 和回撤阈值转换为 `null`，引擎跳过对应判断。

“为什么这样理解？”区域展示用户表达、对应指标和筛选条件。DeepSeek 返回的 `interpretation` 经过结构校验，并依据已校验条件和输入中出现的预定义短语规范化，不直接展示模型自由文本。规则回退也提供相同说明；未知表达使用通用意图标签，不伪造用户原话。该字段只用于展示，筛选仍使用 `conditions`。手动调整后展示当前阈值，折叠区保留解析结果。走势稳定以60日最大回撤作为简化指标，不等同于波动率。

## 4. AI角色与边界

产品的智能交互层承担三项职责：理解自然语言投资意图、转换结构化条件，以及生成供用户阅读的解释文本。**当前实现将这三项职责分开执行：**

| 职责 | 当前实现 |
| --- | --- |
| 理解自然语言、输出条件 | 通过 OpenAI SDK 兼容方式调用 DeepSeek，模型为 `deepseek-chat` |
| 校验条件与识别部分明确冲突 | JSON 白名单、类型和范围校验，以及本地规则检查 |
| 生成结果解释文本 | `explainer.py` 的确定性模板，只引用已有指标和判断记录，不调用 LLM |
| 生成条件变化说明 | 页面依据两次筛选结果、阈值及缓存是否一致生成说明 |

AI 不负责生成股票名称、价格、实际 PE 或其他金融数据，不预测涨跌，也不提供买卖建议。金融事实来自扶摇金融数据 API；最大回撤由 API 返回的历史收盘价确定性计算。

DeepSeek 请求只包含用户需求和系统约束，不发送股票数据集、缓存或扶摇 API Key。模型输出需通过结构与字段校验；自由文本冲突说明不会直接透传到页面。缺少 `LLM_API_KEY`、API 调用失败、空响应、截断或 JSON 校验失败时，自动回退到本地规则解析。

## 5. 系统架构

| 模块 | 主要职责 |
| --- | --- |
| `src/ai_parser.py` | DeepSeek 意图解析、规则回退、结构校验与冲突处理 |
| `src/fuyao_client.py` | 读取扶摇密钥，调用股票池、估值、财务及历史 K 线接口，校验响应并报告错误 |
| `src/data_pipeline.py` | 批量获取沪深300数据，合并 DataFrame，保存 CSV、数据时间及错误记录 |
| `src/metrics.py` | 数值校验与最大回撤计算 |
| `src/screener.py` | 根据条件进行确定性比较，返回入选状态和逐项判断记录 |
| `src/explainer.py` | 将已有指标与判断转为自然语言解释卡片 |
| `app.py` | 输入、解析展示、阈值确认、缓存筛选、结果详情及条件变化分析 |

数据准备与页面交互分开运行：流水线负责联网取数，页面在执行筛选时读取本地 CSV。调整阈值不会触发金融 API 请求。

## 6. 数据来源

金融数据源为**扶摇金融数据 API**，客户端使用 `X-api-key` 鉴权。

| 数据 | 已接入接口 | 用途 |
| --- | --- | --- |
| 沪深300成分股 | `/api/a-share-index/constituents/ths-stock-list` | 使用 `000300.SH` 获取股票池、代码和名称 |
| 股票估值数据 | `/api/a-share/valuations/snapshot` | 获取 `pe_ttm` |
| 财务指标 | `/api/a-share/financials/indicators` | 获取指定报告期的 `calculate_operating_income_yoy_growth_ratio` |
| 历史 K 线 | `/api/a-share/prices/historical` | 获取前复权日线的 `date_ms`、`close_price`，计算最大回撤 |

流水线输出 `data/stock_dataset.csv`：

| 字段 | 含义与处理 |
| --- | --- |
| `code` | 股票代码，来自成分股接口 |
| `name` | 股票名称，来自成分股接口 |
| `revenue_yoy` | 营业收入同比增长率，将 API 原始数值字符串转为数值；详情按百分数展示 |
| `pe_ttm` | 滚动市盈率，保留 API 返回的数值，包括负值 |
| `max_drawdown` | 最近60根前复权日K线的最大回撤比例；`0.15` 表示15% |

数据可信性通过以下机制支持：

- 单项请求失败或指标缺失时记录错误，保留股票身份，对应指标为 `NaN`；CSV 中为空单元格，不补零、不生成金融占位值。
- 股票池获取失败时抛出错误，不覆盖已有缓存。
- `data/stock_dataset.meta.json` 保存来源、构建时间、报告期、K线截止日期、各股票实际行情窗口、缺失数量及错误记录。
- 页面显示缓存的构建时间、财报期与K线截止日期；缺失指标不会被当作符合条件。
- CSV 和元数据文件分别采用临时文件写入后替换，减少写入中断产生残缺文件的风险。

来源标签与日志提供可追溯信息，但不构成对本地文件未被修改的认证。

## 7. 当前筛选规则

| 需求 | 判断规则 | 默认参数 |
| --- | --- | --- |
| 经营改善 | 营业收入同比增长率 `> 0` | `growth_improvement = true` |
| 估值合理 | `PE(TTM) < 用户设定阈值` | `pe_max = 30` |
| 走势稳定 | `60日最大回撤 < 用户设定阈值` | `max_drawdown_max = 0.15` |

所有启用条件采用 **AND** 关系；PE 和回撤使用严格小于，因此等于阈值不通过。`growth_improvement = false` 表示不启用经营改善条件。缺失或非法指标对应的启用条件判为未通过。

最大回撤按日期升序的收盘价计算：

```text
当日回撤 =（截至当日的窗口内最高收盘价 − 当日收盘价）/ 窗口内最高收盘价
最大回撤 = 窗口内各日回撤的最大值
```

“60日”在当前实现中指最近60根可用日K线。流水线依次尝试120、240、365个自然日的取数范围，仍不足60根时保留缺失值。北京时间15点前排除当日K线，15点后允许使用接口已返回的当日数据。

这些映射是产品的预定义策略参数，不是行业通用的估值或经营质量结论。当前 PE 规则没有额外的正值限制，负 PE 可能通过上限条件。

## 8. 可解释机制

筛选引擎为每只股票返回 `code`、`name`、`selected`、`reasons` 和 `failed_conditions`，保留每项条件的指标值、比较符、阈值、启用状态和通过状态。

股票详情展示：

- **条件匹配数量**：如 `3/3`，未启用条件不计入分母。
- **已满足条件与未满足条件**：分别列出通过与未通过项目。
- **当前数据**：只使用 `revenue_yoy`、`pe_ttm`、`max_drawdown`。
- **筛选要求**：显示本次确认的阈值。
- **自然语言原因**：例如营收同比下降时，说明其未满足经营改善条件。

卡片数值按两位小数展示，筛选使用原始精度。解释器不直接采用上游自由文本 `message`，也不推测缺失指标；没有唯一有效判断记录时明确提示待核对。模型不参与股票是否入选的判定。

## 9. 条件变化分析

用户调整 PE 或最大回撤阈值并重新执行后，页面与**同一轮需求下上一次成功筛选**比较，展示：

- 调整前候选数量。
- 调整后候选数量。
- 新增数量：新候选集合中此前不存在的股票数。
- 减少数量：原候选集合中本次不再入选的股票数。

新增与减少按股票代码集合计算，不只展示候选总数的差值。说明文本依据实际阈值方向与集合变化生成；多项条件同时调整时说明共同影响，不归因于某一条件。

修改阈值会隐藏旧展示结果，但保留对比基准；执行失败不会丢失上一次成功快照。修改自然语言需求或重新解析会清空基准。若两次缓存数据不同，页面明确提示不能仅将结果变化归因于阈值调整。当前对比保存在 Streamlit 会话内，不提供持久化历史记录。

## 10. 安装与运行

建议使用 Python 3.11 或更新版本。以下命令在项目根目录的 Windows PowerShell 中执行。

**创建虚拟环境并安装依赖：**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**配置环境变量：**

首次使用且不存在 `.env` 时，将 `.env.example` 复制为 `.env`，在本地填入密钥。已有 `.env` 时保留现有文件。

```dotenv
FUYAO_API_KEY=
LLM_API_KEY=
```

**准备真实股票数据：**

```powershell
.\.venv\Scripts\python.exe -X utf8 -m src.data_pipeline
```

该命令调用真实金融 API，生成 CSV 与元数据缓存，可能需要数分钟。默认财报期为当前已结束的最近自然季度，不保证每家公司都已披露。也可明确指定统一报告期：

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "from src.data_pipeline import build_stock_dataset; build_stock_dataset(report='2026-2')"
```

`2026-2` 为中报报告期示例，请根据使用场景选择。程序不会自动回退到其他报告期。

**启动页面：**

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

浏览器访问终端给出的地址，默认是 `http://localhost:8501`。输入“经营改善、估值合理、走势稳定”，解析后确认阈值，即可筛选和查看详情。

页面缺少 CSV 时会提示先生成数据。数据不会在页面中自动刷新；需要更新时重新运行流水线。已存在缓存时，页面筛选无需调用扶摇 API。

## 11. 环境变量

| 变量 | 用途 | 未配置时的行为 |
| --- | --- | --- |
| `FUYAO_API_KEY` | 扶摇金融数据 API 鉴权 | 真实取数失败；已有 CSV 的页面筛选仍可运行 |
| `LLM_API_KEY` | DeepSeek 意图解析鉴权 | 自动使用本地规则解析 |

通过 `python-dotenv` 加载项目根目录 `.env`，已存在的进程环境变量优先。DeepSeek 地址固定为 `https://api.deepseek.com`，模型固定为 `deepseek-chat`。

`.env.example` 仅保留空值模板。`.env`、环境变体、Streamlit 本地配置和 `data/` 下的 CSV、JSON 已配置 Git 忽略规则；不应将真实密钥写入 README、代码或提交记录。

## 12. 测试

测试使用 Python `unittest`；页面交互使用 Streamlit `AppTest`。

| 覆盖范围 | 测试文件与内容 |
| --- | --- |
| API 调用 | `test_fuyao.py`、`test_valuation.py`、`test_financial.py`、`test_kline.py`：真实接口与返回字段、行情和回撤计算 |
| 数据流水线 | `test_pipeline.py`：股票数量、字段完整性、缓存读写、缺失处理和失败时保留旧缓存 |
| 筛选逻辑 | `test_core.py`、`test_screener.py`：边界比较、缺失指标、条件启用状态与逐项判断 |
| AI 解析 | `test_ai_parser.py`、`test_ai_parser_llm.py`：正常、模糊、冲突需求，以及模型失败和非法 JSON 回退 |
| 结果解释 | `test_result_cards.py`：真实缓存数值格式、自然语言原因和缺失记录处理 |
| 页面交互 | `test_app.py`：澄清拦截、阈值调整、详情展示、缓存缺失、结果对比及失败重试 |

运行完整测试：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

完整测试需要有效的 `FUYAO_API_KEY` 和网络连接，包含沪深300全量取数，会更新本地缓存，执行可能需要数分钟。部分集成测试固定使用 `2026-2` 报告期。

单独运行页面或模型回退测试：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_app.py -v
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_ai_parser_llm.py -v
```

页面测试固定走规则回退；依赖真实缓存的用例在缓存不存在时跳过。LLM 单元测试模拟模型响应和故障，不调用 DeepSeek，也不证明实时模型调用成功。流水线异常测试使用故障注入验证留空处理，不将模拟金融数值写入正式缓存；旧版核心规则测试包含隔离的合成数值。

## 13. 已知限制

- **股票池范围**：当前仅覆盖沪深300成分股，不覆盖全市场。
- **条件表达能力**：采用预定义指标映射，只支持经营改善、PE 上限和最大回撤上限；不支持任意策略、复杂逻辑组合或行业适配。
- **语义理解**：模型解析可能出错；结构校验不能保证语义完全正确，需要用户确认条件。规则回退的语言覆盖范围更窄。
- **财务口径**：经营改善目前仅看营收同比，不是连续多个报告期的经营改善分析；默认报告期可能尚未披露，不自动切换报告期。
- **数据时效**：页面使用本地缓存，没有自动刷新或实时行情推送；不同指标不保证同一时点更新。
- **走势口径**：最大回撤基于最近60根可用前复权日K线，遇到停牌等情况，其自然日跨度可能不同；没有历史策略回测或未来收益评估。
- **解释范围**：解释由模板基于规则与已有字段生成，不包含行业研究、估值判断或基本面因果分析。
- **产品边界**：不提供投资建议，不预测涨跌或未来收益。入选只表示匹配当前条件，不代表买入信号或收益承诺。
